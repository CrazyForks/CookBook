## 2. 各区域详解

### 2.1 程序计数器（PC Register）

```
程序计数器:
- 线程私有，每个线程一个
- 记录当前执行的字节码行号
- 唯一不会 OOM 的区域
- 执行 Native 方法时为空（Undefined）
```

### 2.2 虚拟机栈（VM Stack）

```
虚拟机栈结构:

每个方法调用创建一个栈帧（Stack Frame）:

┌─────────────────────────────────────┐
│            栈帧 (Stack Frame)       │
├─────────────────────────────────────┤
│  局部变量表 (Local Variables)       │  ← 存放方法参数和局部变量
│  操作数栈 (Operand Stack)           │  ← 存放中间计算结果
│  动态链接 (Dynamic Linking)         │  ← 指向运行时常量池
│  方法返回地址 (Return Address)      │  ← 方法返回位置
└─────────────────────────────────────┘

栈溢出:
- StackOverflowError: 栈深度超过限制
- OutOfMemoryError: 栈扩展失败

参数:
-Xss256k  设置栈大小（默认 512k-1m）
```

### 2.3 堆（Heap）

```
堆内存分代:

┌─────────────────────────────────────────────────────────────┐
│                         堆 (Heap)                           │
├─────────────────────────────────────────────────────────────┤
│  ┌───────────────────────────────┐  ┌───────────────────┐  │
│  │          新生代               │  │      老年代       │  │
│  │  ┌─────────┬─────┬─────┐     │  │                   │  │
│  │  │  Eden   │  S0 │  S1 │     │  │                   │  │
│  │  │  80%    │ 10% │ 10% │     │  │                   │  │
│  │  └─────────┴─────┴─────┘     │  │                   │  │
│  │         Young Generation     │  │  Old Generation   │  │
│  └───────────────────────────────┘  └───────────────────┘  │
│                                                             │
│  默认比例: 新生代:老年代 = 1:2                              │
│  Eden:S0:S1 = 8:1:1                                        │
└─────────────────────────────────────────────────────────────┘

对象分配流程:
1. 新对象优先在 Eden 分配
2. Eden 满时触发 Minor GC
3. 存活对象进入 Survivor 区（S0/S1）
4. 年龄达到阈值（默认15）进入老年代
5. 老年代满时触发 Major GC / Full GC
```

### 2.4 方法区（Method Area）

```
方法区演变:

JDK7 及之前: 永久代（PermGen）
- 存储类信息、常量、静态变量
- -XX:PermSize -XX:MaxPermSize
- 容易 OOM

JDK8+: 元空间（Metaspace）
- 使用本地内存，不在堆中
- -XX:MetaspaceSize -XX:MaxMetaspaceSize
- 默认无限制（受系统内存限制）

存储内容:
- 类的元数据（Class Metadata）
- 运行时常量池（Runtime Constant Pool）
- 静态变量（JDK7+移到堆中）
- JIT 编译后的代码
```

## 3. 垃圾回收算法

```
GC 算法对比:

┌──────────────┬──────────────┬──────────────┬──────────────┐
│ 算法         │ 原理         │ 优点         │ 缺点         │
├──────────────┼──────────────┼──────────────┼──────────────┤
│ 标记-清除    │ 标记存活对象 │ 简单         │ 内存碎片     │
│              │ 清除未标记   │              │ 效率低       │
├──────────────┼──────────────┼──────────────┼──────────────┤
│ 标记-整理    │ 标记存活对象 │ 无碎片       │ 效率低       │
│              │ 向一端移动   │              │ 移动成本高   │
├──────────────┼──────────────┼──────────────┼──────────────┤
│ 复制算法     │ 分两块       │ 无碎片       │ 空间浪费     │
│              │ 复制存活对象 │ 效率高       │ 50%利用率    │
├──────────────┼──────────────┼──────────────┼──────────────┤
│ 分代收集     │ 新生代+老年代│ 综合优化     │ 实现复杂     │
│              │ 不同算法     │              │              │
└──────────────┴──────────────┴──────────────┴──────────────┘
```

## 4. 垃圾收集器

```
垃圾收集器演进:

┌─────────────────────────────────────────────────────────────┐
│                    垃圾收集器                               │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  新生代收集器:                                              │
│  ├── Serial:      单线程，复制算法，STW                     │
│  ├── ParNew:      多线程 Serial，配合 CMS                   │
│  └── Parallel Scavenge: 吞吐量优先                         │
│                                                             │
│  老年代收集器:                                              │
│  ├── Serial Old:  单线程，标记-整理                         │
│  ├── CMS:         并发标记清除，低延迟                      │
│  └── Parallel Old: 吞吐量优先                              │
│                                                             │
│  整堆收集器:                                                │
│  ├── G1:          分 Region，可预测停顿（JDK9默认）        │
│  ├── ZGC:         亚毫秒级停顿（JDK15正式）                │
│  └── Shenandoah:  低延迟（RedHat）                         │
│                                                             │
└─────────────────────────────────────────────────────────────┘

收集器选择:
┌──────────────┬──────────────┬──────────────┐
│ 场景         │ 推荐收集器   │ 关键参数     │
├──────────────┼──────────────┼──────────────┤
│ 低延迟       │ ZGC          │ -XX:+UseZGC  │
│ 高吞吐       │ Parallel     │ -XX:+UseParallelGC │
│ 大堆(4G+)    │ G1           │ -XX:+UseG1GC │
│ 传统应用     │ CMS+ParNew   │ -XX:+UseConcMarkSweepGC │
└──────────────┴──────────────┴──────────────┘
```

## 5. G1 收集器详解

```
G1 收集器特点:

┌─────────────────────────────────────────────────────────────┐
│                    G1 Region 布局                           │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  ┌────┬────┬────┬────┬────┬────┬────┬────┬────┬────┐      │
│  │ E  │ E  │ S  │ O  │ O  │ H  │ H  │ E  │ S  │ E  │      │
│  └────┴────┴────┴────┴────┴────┴────┴────┴────┴────┘      │
│                                                             │
│  E: Eden      新生代                                        │
│  S: Survivor  幸存区                                        │
│  O: Old       老年代                                        │
│  H: Humongous 大对象（> Region 50%）                        │
│                                                             │
│  特点:                                                      │
│  - 将堆划分为多个大小相等的 Region（1-32MB）                │
│  - 每个 Region 可以是任意角色                               │
│  - 可预测的停顿时间模型                                     │
│  - 优先回收价值最大的 Region                                │
│                                                             │
└─────────────────────────────────────────────────────────────┘

G1 关键参数:
-XX:+UseG1GC                    启用 G1
-XX:G1HeapRegionSize=16m        Region 大小
-XX:MaxGCPauseMillis=200        目标停顿时间
-XX:G1ReservePercent=25         预留内存百分比
-XX:InitiatingHeapOccupancyPercent=30  触发 GC 的堆占用比例
```
