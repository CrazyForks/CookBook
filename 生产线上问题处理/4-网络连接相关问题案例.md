# 生产问题案例 - 网络/连接相关（案例 23-28）

## 案例23: 连接池耗尽导致服务不可用

### 问题现象
- 接口报错 "Connection pool exhausted"
- 服务无法处理新请求
- 连接池使用率 100%

### 排查过程
```bash
# 查看连接数
netstat -an | grep ESTABLISHED | wc -l

# 查看连接状态
netstat -an | awk '/^tcp/ {++state[$NF]} END {for(key in state) print key, state[key]}'

# 查看数据库连接池状态
# HikariCP 日志
# HikariPool-1 - Pool stats (total=10, active=10, idle=0, waiting=50)
```

### 根因分析
```java
// 问题代码: 连接未归还
public void queryData() {
    Connection conn = dataSource.getConnection();
    try {
        PreparedStatement ps = conn.prepareStatement("SELECT * FROM users");
        ResultSet rs = ps.executeQuery();
        // 处理结果
        // 忘记关闭连接
    } catch (SQLException e) {
        // 异常时连接未归还
    }
}

// 另一个问题: 连接池配置过小
HikariConfig config = new HikariConfig();
config.setMaximumPoolSize(5);  // 太小
```

### 解决方案
```java
// 方案1: 使用 try-with-resources
public void queryData() {
    try (Connection conn = dataSource.getConnection();
         PreparedStatement ps = conn.prepareStatement("SELECT * FROM users");
         ResultSet rs = ps.executeQuery()) {
        // 处理结果
    }
}

// 方案2: 使用 JdbcTemplate
@Autowired
private JdbcTemplate jdbcTemplate;

public List<User> queryUsers() {
    return jdbcTemplate.query("SELECT * FROM users", (rs, rowNum) -> {
        User user = new User();
        user.setId(rs.getLong("id"));
        user.setName(rs.getString("name"));
        return user;
    });
}

// 方案3: 合理配置连接池
HikariConfig config = new HikariConfig();
config.setMaximumPoolSize(20);          // 最大连接数
config.setMinimumIdle(5);               // 最小空闲连接
config.setConnectionTimeout(30000);     // 连接超时 30秒
config.setIdleTimeout(600000);          // 空闲超时 10分钟
config.setMaxLifetime(1800000);         // 最大生命周期 30分钟
config.setLeakDetectionThreshold(60000); // 泄漏检测 60秒
```

## 案例24: TIME_WAIT 连接过多

### 问题现象
- 服务器大量 TIME_WAIT 连接
- 无法建立新连接
- 端口耗尽

### 排查过程
```bash
# 查看 TIME_WAIT 数量
netstat -an | grep TIME_WAIT | wc -l

# 输出: 50000+

# 查看连接状态分布
netstat -an | awk '/^tcp/ {++state[$NF]} END {for(key in state) print key, state[key]}'

# 输出:
# ESTABLISHED 1000
# TIME_WAIT   50000
# CLOSE_WAIT  100
```

### 根因分析
```
问题原因:
1. HTTP 短连接频繁创建关闭
2. 负载均衡器健康检查频繁连接
3. 客户端未使用连接池

# TIME_WAIT 状态持续 2*MSL（默认60秒）
# 大量短连接导致端口耗尽
```

### 解决方案
```bash
# 方案1: 调整内核参数
# /etc/sysctl.conf
net.ipv4.tcp_tw_reuse = 1           # 重用 TIME_WAIT
net.ipv4.tcp_fin_timeout = 30       # FIN 超时时间
net.ipv4.tcp_max_tw_buckets = 10000 # TIME_WAIT 最大数量
net.ipv4.ip_local_port_range = 1024 65535  # 端口范围

# 生效
sysctl -p

# 方案2: 使用长连接
# Nginx 配置
upstream backend {
    server 127.0.0.1:8080;
    keepalive 32;  # 保持 32 个长连接
}

# 方案3: 客户端使用连接池
RestTemplate restTemplate = new RestTemplate();
// 或使用 OkHttp、Apache HttpClient 连接池
```

## 案例25: CLOSE_WAIT 连接泄漏

### 问题现象
- 服务器大量 CLOSE_WAIT 连接
- 连接数持续增长
- 最终无法建立新连接

### 排查过程
```bash
# 查看 CLOSE_WAIT 数量
netstat -an | grep CLOSE_WAIT | wc -l

# 查看 CLOSE_WAIT 连接详情
netstat -anp | grep CLOSE_WAIT

# 输出:
# tcp  0  0  127.0.0.1:8080  127.0.0.1:12345  CLOSE_WAIT  1234/java

# 查看进程
lsof -i :8080 | grep CLOSE_WAIT
```

### 根因分析
```java
// 问题代码: 服务端未正确关闭连接
public void handleRequest(InputStream is, OutputStream os) {
    // 读取请求
    byte[] data = readAll(is);
    
    // 处理请求
    String response = process(data);
    
    // 发送响应
    os.write(response.getBytes());
    os.flush();
    
    // 忘记关闭连接
    // is.close();
    // os.close();
}

// CLOSE_WAIT 表示被动关闭方未调用 close()
```

### 解决方案
```java
// 方案1: 正确关闭连接
public void handleRequest(Socket socket) {
    try (InputStream is = socket.getInputStream();
         OutputStream os = socket.getOutputStream()) {
        byte[] data = readAll(is);
        String response = process(data);
        os.write(response.getBytes());
        os.flush();
    } finally {
        socket.close();
    }
}

// 方案2: 使用 HTTP 客户端连接池
CloseableHttpClient httpClient = HttpClients.custom()
    .setConnectionManager(new PoolingHttpClientConnectionManager())
    .setKeepAliveStrategy((response, context) -> {
        return TimeValue.ofSeconds(30);
    })
    .build();

// 方案3: 监控和清理
@Scheduled(fixedRate = 60000)
public void cleanupConnections() {
    // 清理过期连接
}
```

## 案例26: 端口耗尽无法新建连接

### 问题现象
- 报错 "Cannot assign requested address"
- 无法建立新 TCP 连接
- 短连接场景下出现

### 排查过程
```bash
# 查看端口使用情况
netstat -an | grep ESTABLISHED | wc -l

# 查看临时端口范围
cat /proc/sys/net/ipv4/ip_local_port_range
# 输出: 32768 60999

# 查看 TIME_WAIT 数量
netstat -an | grep TIME_WAIT | wc -l
```

### 根因分析
```
问题原因:
1. 临时端口范围有限（32768-60999，约28000个）
2. TIME_WAIT 连接占用端口
3. 客户端频繁创建短连接

# 每个客户端 IP:PORT 组合唯一
# 短连接关闭后进入 TIME_WAIT（60秒）
# 端口被 TIME_WAIT 占用，无法复用
```

### 解决方案
```bash
# 方案1: 扩大临时端口范围
echo "1024 65535" > /proc/sys/net/ipv4/ip_local_port_range
# 或
sysctl -w net.ipv4.ip_local_port_range="1024 65535"

# 方案2: 启用 TIME_WAIT 重用
sysctl -w net.ipv4.tcp_tw_reuse=1

# 方案3: 使用长连接
# 减少短连接创建

# 方案4: 使用多 IP
# 绑定多个客户端 IP，增加可用端口
```

## 案例27: 网络抖动导致超时

### 问题现象
- 接口偶发超时
- 错误日志显示连接超时或读取超时
- 网络监控显示丢包

### 排查过程
```bash
# 测试网络连通性
ping -c 100 target-server

# 查看丢包率
# 100 packets transmitted, 95 received, 5% packet loss

# 查看网络延迟
# rtt min/avg/max/mdev = 0.5/2.5/15.0/3.0 ms

# 查看网络接口错误
netstat -i

# 查看交换机日志
# 检查网络设备
```

### 根因分析
```
问题原因:
1. 网络设备故障
2. 带宽饱和
3. 网络拥塞
4. 物理线路问题

# 5% 的丢包会导致:
# - TCP 重传增加
# - 延迟增大
# - 超时发生
```

### 解决方案
```bash
# 方案1: 调整超时时间
# 连接超时
connectTimeout=3000
# 读取超时
readTimeout=5000

# 方案2: 配置重试
# 最大重试次数
maxRetries=3
# 重试间隔
retryInterval=1000

# 方案3: 使用更可靠的网络
# - 双线路冗余
# - BGP 多线接入
# - 专线连接

# 方案4: 服务降级
# 网络不稳定时降级处理
```

## 案例28: DNS 解析超时

### 问题现象
- 服务启动时连接注册中心超时
- 调用外部服务偶发超时
- DNS 解析耗时长

### 排查过程
```bash
# 测试 DNS 解析
nslookup example.com

# 查看 DNS 响应时间
time nslookup example.com

# 查看 DNS 配置
cat /etc/resolv.conf

# 查看 DNS 缓存
# systemd-resolve --statistics
```

### 根因分析
```
问题原因:
1. DNS 服务器响应慢
2. DNS 服务器故障
3. 网络到 DNS 服务器不通
4. DNS 缓存失效

# /etc/resolv.conf
nameserver 8.8.8.8    # Google DNS
nameserver 114.114.114.114  # 国内 DNS
```

### 解决方案
```bash
# 方案1: 配置多个 DNS 服务器
# /etc/resolv.conf
nameserver 114.114.114.114
nameserver 8.8.8.8
nameserver 8.8.4.4
options timeout:2 attempts:3

# 方案2: 使用本地 DNS 缓存
# 安装 nscd
yum install nscd
systemctl start nscd

# 方案3: 使用 IP 地址代替域名
# 在配置中直接使用 IP

# 方案4: 配置 DNS 超时
# /etc/resolv.conf
options timeout:2 attempts:3 rotate

# 方案5: 使用服务发现
# Nacos、Consul、Zookeeper
```
